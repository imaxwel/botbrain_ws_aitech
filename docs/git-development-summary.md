## 一、总体结论

`eb4115880fc36debfbafc964e4a0698619ab908d` 是仓库的初始提交，因此本报告覆盖了项目从创建到当前版本的完整 Git 历史。

该范围共包含：

- 73 个提交，其中 67 个为非合并提交；
- 163 个变更文件；
- 24,381 行新增；
- 2,135 行删除；
- 提交作者均为同一开发者邮箱身份的不同写法，因此可视为完整的个人工程贡献记录。

项目工作的核心，不是简单修改导航参数，而是将一个基础的 Unitree G1 ROS2 工程逐步建设为能够在真实室内场地运行的完整机器人系统，覆盖：

- MID360 与 IMU 数据校正；
- FAST-LIO 建图与定位稳定性；
- 点云到二维栅格和导航障碍物的转换；
- Open3D 全局定位与 ICP 局部匹配；
- Nav2 路径规划、到点执行和动态避障；
- 地图制作、修图、保存和场景管理；
- 多地图和跨楼层切换；
- 电梯到达后的安全重新定位；
- RViz2、Foxglove 和跨机器 ROS2 通信；
- 香港现场无 Wi-Fi 网络部署与调试；
- 自动化测试、运行手册和交接文档。

最终形成的系统链路如下：

```text
MID360 + IMU
    ↓  坐标校正、外参修正、初始化与时序健康检查
FAST-LIO
    ↓  点云、里程计、地图基准
点云投影与二维栅格生成
    ↓  /scan、局部障碍物、二维地图
Open3D 全局定位 + ICP 局部匹配
    ↓  定位质量、一致性和场景验收
Nav2 + 行为树 + Waypoint + Costmap
    ↓
G1 实机导航、避障、多地图和跨楼层运行
```

## 三、核心技术改进

### 3.1 解决 G1 运动过程中的 FAST-LIO 漂移

这一部分是后续定位与导航能够工作的基础。

主要完成了：

- 将 IMU 输入从未经处理的原始话题调整为经过安装方向校正后的 `/livox/imu_corrected`；
- 明确区分“LiDAR 到内置 IMU 的外参”和“传感器离地高度”；
- 修正曾经将 `1.247m` 离地高度误用为传感器内部外参的问题；
- 根据双足机器人平衡动作的噪声特征调整加速度计和陀螺仪协方差；
- 调整 ICP 迭代次数、点云滤波粒度和局部匹配条件；
- 增加 IMU 初始化、传感器时序连续性和输出健康状态检查；
- 优化 FAST-LIO 停止信号和 PCD 保存超时，避免退出时卡死或破坏地图；
- 区分建图和定位模式下的 `pcd_save_en`，防止导航退出时覆盖已有地图。

解决的问题：

- 转弯时点云旋转偏移；
- 左右横移时墙体重影；
- 前进时地图逐渐拉伸；
- 错误外参导致点云整体倾斜或高度不正确；
- FAST-LIO 尚未稳定时，定位和导航已经开始消费错误数据。

取得的效果：

- 将 FAST-LIO 从“进程启动成功”提升为“初始化、时序和输出均健康才可使用”；
- 降低机器人运动导致地图不可恢复漂移的概率；
- 为 Open3D 定位、二维栅格生成和 Nav2 提供一致的点云与里程计基准。

### 3.2 将点云转换为可用于导航的地图和障碍物

点云能够显示，不等于能够直接用于导航。为此完成了：

- 根据传感器离地高度定义地面、障碍物、天花板和下台阶的高度区间；
- 过滤天花板和超高点，避免它们投影到二维 Costmap；
- 将低于地面的危险区域识别为下台阶或跌落障碍；
- 增加 `min_obs_hits` 多帧命中阈值，降低单帧噪点和移动行人的影响；
- 修正二维栅格在三维视图中的 Z 高度；
- 抽离 `grid_mapping_core.py`，将栅格处理做成可测试的核心模块；
- 新增 `navigation_scan_projector.py`，专门生成导航使用的扫描和障碍物输入；
- 调整 pointcloud-to-laserscan、障碍物层、体素层和膨胀层参数。

解决的问题：

- 地面被识别成障碍，导致栅格图全黑；
- 现场行人经过后留下永久假障碍；
- 天花板和机器人自身结构进入局部 Costmap；
- 点云可以看见，但 Nav2 无法稳定消费；
- 障碍物膨胀过大导致走廊无法通过，过小又导致安全距离不足。

取得的效果：

- 形成稳定的“3D 点云 → 2D 地图/扫描 → Nav2 Costmap”数据链路；
- 改善走廊、近障、动态障碍物场景的通过性；
- 通过后续多次实机提交持续收敛障碍物膨胀和路径流畅性。

### 3.3 将定位升级为经过验收的可信定位

在 Open3D 定位链路中，完成了以下改进：

- 使用多尺度 FPFH 特征，降低单一体素尺度对不同建筑结构的依赖；
- 将 RANSAC 定位结果视为候选，而不是直接作为最终位姿；
- 使用精细 ICP 的 fitness、RMSE 和重叠质量验收候选；
- 要求候选连续多次满足平移和旋转一致性；
- 使用滚动点云窗口，为缓慢转向时的定位增加墙角等几何特征；
- 检查当前点云点数、跨度和有效量程，低质量点云不进入跨层定位；
- 为电梯出口增加局部先验搜索；
- 没有先验时使用二维 BBS Top-K 候选，再通过原有 ICP 验证；
- BBS 和局部 ICP 均失败后，才回退到全局 FPFH/RANSAC。

解决的问题：

- 对称走廊或重复结构中，定位容易匹配到错误区域；
- 单帧点云信息不足时产生错误全局位姿；
- 电梯轿厢内点云缺乏可定位性，却仍不断消耗定位尝试；
- 地图已切换，但定位尚未稳定时 Nav2 已经开始运行。

取得的效果：

- 定位从“得到一个匹配结果”变为“满足质量、一致性和场景检查后才接受”；
- 跨楼层定位可以优先利用电梯出口先验，减少全局盲搜；
- 定位失败时保持导航停止，避免错误位姿驱动机器人运动。

### 3.6 实现多地图与跨楼层安全切换

跨楼层功能不是简单调用 `/map_server/load_map`，而是完整的运行时事务。

主要完成了：

- 显式维护楼层号到场景名的映射；
- 校验 `<scene>_scans.pcd`、`<scene>.yaml`、`<scene>.pgm` 均存在且匹配；
- 停止旧 Navigation 和 localization；
- 跨楼层时重新启动 FAST-LIO，建立新楼层的高度和里程计基准；
- 清除残留 localization 容器，避免旧 `/map` 或 `/pcd_map` 发布者污染 ROS 图；
- 检查运行容器实际加载的 PCD、YAML 和场景参数；
- 等待 FAST-LIO 初始化、时序连续、点云和里程计输出正常；
- 等待自动定位通过并验证发布者唯一性；
- 只有所有检查通过后才重新启动 Navigation；
- 使用文件锁阻止多个切图事务并发执行；
- 切图失败时保持导航停止，并按错误类别决定重试或人工处理。

楼层触发侧增加了：

- `expected_floor` 显式任务解锁；
- 楼层消息类型、发布者数量和 QoS 检查；
- 相同楼层连续多次且持续一定时间的稳定确认；
- 消息新鲜度检查；
- 机器人线速度和角速度静止门控；
- 可选的 `arrival_confirmed` 到达确认；
- `from_floor + target_floor + elevator_id` 电梯路线先验；
- 最大重试次数和重试间隔；
- `IDLE`、`ARMED`、`LOCALIZING`、`RETRY_WAIT`、`READY`、`FAILED` 状态输出。

取得的效果：

- 避免 2D 地图、3D PCD 和 FAST-LIO 坐标基准错配；
- 避免历史楼层消息或话题抖动触发误切图；
- 避免机器人仍在电梯中运动时开始定位或导航；
- 上层任务可以明确判断跨楼层任务成功、等待或失败。

### 3.7 增加回环检测和位姿图优化

新建了独立的 `g1_loop_closure` ROS2 C++ 包，主要包括：

- 回环检测节点；
- 位姿图数据结构；
- 回环候选几何验证；
- 回环配置文件和启动文件；

### 4.2 无 Wi-Fi 场地和跨机器 ROS2 通信

针对香港现场可能没有固定网络或互联网的问题，设计了三套连接方式：

```text
方案一：机器人和调试电脑连接同一个手机热点
方案二：机器人和调试电脑连接便携路由器
方案三：先通过网线 SSH Jetson，再配置正式 Wi-Fi
```

主要工作包括：

- 不依赖固定 IP，通过机器人 Wi-Fi MAC 查找 DHCP 地址；
- 配置 Wi-Fi 自动连接和优先级；
- 规范 SSH、Foxglove 和 ROS2 服务检查流程；
- 识别和处理热点客户端隔离、不同子网、错误网卡等问题；
- 增加 Zenoh 路由服务和工作站配置；
- 调整 Docker Compose，使 Zenoh 路由器在其他 ROS2 服务前启动；
- 编写 Zenoh 回滚和故障排查步骤；
- 将现场经验整理为可由其他工程师执行的手册。

取得的效果：

- 无互联网时仍可建立机器人与工作站之间的本地调试网络；
- 机器人 IP 发生变化时可重新发现设备；
- 可恢复 SSH、Foxglove/RViz 和 ROS2 跨机器通信；
- 降低现场因网络环境变化而无法继续调试的风险。
